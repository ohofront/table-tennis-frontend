### 3.1 [1] 홈 대시보드 (`/`)

**구성 요소** (엑셀 원문)

| 🏓 오늘의 경기 | 오늘 예정된 경기 리스트 |

| ➕ 경기 등록 버튼 | 경기 추가 화면으로 이동 |

**레이아웃 참고 (사례 시트 ASCII 목업)**
```
+------------------------------------------------------------+
|                      홈 대시보드                            |
+------------------------------------------------------------+
| 오늘의 경기              | 상위 랭킹 선수                 |
|--------------------------|-------------------------------|
| - 김철수 vs 이영희       | 1위: 이영희 (승률 82%)        |
| - 박민수 vs 최지훈       | 2위: 김철수 (승률 78%)        |
|                          | 3위: 홍길동 (승률 75%)        |
+------------------------------------------------------------+
| 최근 경기 결과                                           ⏱ |
|------------------------------------------------------------|
| [4/14] 김철수 2 : 1 홍길동    |  [4/13] 이영희 3 : 0 박민수  |
+------------------------------------------------------------+
| [+] 새로운 경기 등록                                        |
+------------------------------------------------------------+
```

**사용 API**
- `GET /api/v1/dashboard/today-matches`
- `GET /api/v1/dashboard/top-players`
- `GET /api/v1/dashboard/recent-results`

**인터랙션**
- "새로운 경기 등록" 버튼 → `/matches/new` 이동 (ADMIN 권한 없으면 로그인/권한 안내 모달).
- 최근 경기결과 카드 클릭 → `/matches/[matchId]` 상세 이동.

### 3.2 [2] 선수 관리 화면 (`/players`)

**구성 요소**
| 요소 | 설명 |
|---|---|
| 선수 목록 테이블 | 이름, 닉네임, 소속, 승률 등 |
| 검색 및 필터 | 이름, 클럽, 성별 검색 |
| 프로필 보기 | 사진, 생년월일, 총 경기 수 등 |
| 선수 추가/수정 버튼 | 신규 등록 또는 정보 변경 (ADMIN) |

**레이아웃 참고**
```
+------------------------------------------------------------+
|                        선수 관리                           |
+------------------------------------------------------------+
| [🔍 이름/클럽 검색]   [성별 ♂ ♀] [승률순 ▼] [추가 버튼 +]   |
+------------------------------------------------------------+
| 이름     | 클럽     | 승률 | 총 경기 | 상세 보기 | 수정 |
|----------|----------|------|----------|-----------|------|
| 이영희   | A클럽     | 82%  | 45경기   | [보기]    | ✎    |
| 김철수   | B클럽     | 78%  | 50경기   | [보기]    | ✎    |
| 박민수   | 무소속     | 65%  | 30경기   | [보기]    | ✎    |
+------------------------------------------------------------+
```

**사용 API**
- `GET /api/v1/users?keyword=&club=&gender=&sort=winRate,desc` (목록, 검색/필터/정렬)
- `GET /api/v1/users/{userId}` (프로필 상세, 모달 또는 3.3 상세 페이지)
- `POST /api/v1/auth/signup` 또는 관리자용 등록 엔드포인트 (ADMIN, 참가선수 신규 등록 시)
- `PUT /api/v1/users/{userId}` (수정)

**검증 규칙**
- 검색어 300ms debounce.
- 성별 필터: 전체/M/F.
- 정렬: 승률순/경기수순/최근등록순.

### 3.4 [3] 경기 등록 화면 (`/matches/new`)

**구성 요소**
| 요소 | 설명 |
|---|---|
| 선수 선택 | Player 1 / Player 2 (드롭다운 또는 검색) — 단식 기준, 복식/단체전은 참가자 다중 선택으로 확장 |
| 경기 날짜 및 장소 입력 | 달력 + 텍스트 입력 |
| 경기 라운드 선택 | 예선, 결승 등 |
| 메모 | 자유 입력 |
| 다음 버튼 | 세트 입력 화면(3.5)으로 이동 |

**레이아웃 참고**
```
+------------------------------------------------------------+
|                       경기 등록                             |
+------------------------------------------------------------+
| 선수 1 선택 : [ 김철수 ▼ ]                                  |
| 선수 2 선택 : [ 이영희 ▼ ]                                  |
| 경기 날짜   : [ 2026-04-16 🗓 ]                              |
| 경기 장소   : [ 포항체육관 ]                                 |
| 경기 라운드 : [ 예선 ▼ ]                                     |
| 비고 메모   : [ ______________________________ ]            |
+------------------------------------------------------------+
| [다음 ➡ 세트 점수 입력]                                     |
+------------------------------------------------------------+
```

**폼 필드 및 검증**
| 필드 | 타입 | 검증 |
|---|---|---|
| competitionId | select | 필수, 대회/경기단계 선택 |
| matchFormat | radio | SINGLES/DOUBLES/TEAM (competition의 match_format 자동 반영) |
| participants | 검색형 select (다중) | SINGLES=2명, DOUBLES=4명, TEAM=6명 이상 등 형식별 최소 인원 검증 |
| courtNumber | number | optional |
| notes | textarea | optional, 최대 500자 |

**사용 API**
- `GET /api/v1/users?keyword=` (선수 검색 드롭다운)
- `GET /api/v1/competitions/{id}` (라운드/형식 옵션)
- `POST /api/v1/matches` (등록 — 4.6 참조)

**인터랙션**
- "다음" 클릭 시 `POST /api/v1/matches` 성공 → 응답의 `matchId`로 `/matches/{matchId}/sets`로 라우팅.

### 3.5 [4] 세트 점수 입력 화면 (`/matches/[matchId]/sets`)

**구성 요소**
| 요소 | 설명 |
|---|---|
| 세트별 입력 칸 | 세트1 ~ 세트5 점수 입력 |
| 자동 승자 계산 | 입력 시 누적 승 수 반영 |
| 총 경기 시간(선택) | 입력 필드 또는 자동 기록 |
| 저장 버튼 | 저장 후 경기 상세 화면(3.6) 이동 |

**레이아웃 참고**
```
+------------------------------------------------------------+
|                    세트 점수 입력                          |
+------------------------------------------------------------+
|       | 세트 1 | 세트 2 | 세트 3 | 세트 4 | 세트 5 |        |
|-------|--------|--------|--------|--------|--------|--------|
| 선수1 |   11   |   7    |   11   |        |        |        |
| 선수2 |   9    |  11    |   9    |        |        |        |
+------------------------------------------------------------+
| 총 경기 시간 : [ 00:35:20 ⏱ ]                               |
| 자동 승자 판정 : ✅ 김철수 승리                              |
+------------------------------------------------------------+
| [저장]                                                      |
+------------------------------------------------------------+
```

**클라이언트 로직 (프론트 즉시 반영, 저장 시 서버 값으로 최종 확정)**
1. 세트 점수 입력 시마다 `sideAWins`/`sideBWins` 카운트를 프론트에서 즉시 계산해 "자동 승자 판정" 문구를 실시간으로 갱신 (낙관적 UI).
2. 한 세트는 두 값 모두 입력되어야 유효 세트로 카운트.
3. 11점 이상 & 2점차 이상 도달 시 해당 세트 종료로 하이라이트 (참고용 표시, 서버가 최종 검증).
4. "저장" 클릭 시 `POST /api/v1/matches/{matchId}/sets` 호출, 서버 응답의 최종 승자/상태로 화면 갱신.

**사용 API**
- `POST /api/v1/matches/{matchId}/sets`
- `PUT /api/v1/matches/{matchId}/sets/{setId}` (수정 시)
- `POST /api/v1/matches/{matchId}/finalize` (필요 시 명시적 확정 버튼과 연계)

### 3.8 대회 목록/상세/조편성 (엑셀 기능목록 "대회 경기", "조편성" 대응)

- **대회 목록(`/tournaments`)**: 대회명, 기간, 장소, 상태(예정/진행중/종료) 카드/테이블 목록. `GET /api/v1/tournaments`
- **대회 상세(`/tournaments/[year]/[id]`)**: 탭 구성 — [개요] [참가선수] [조편성] [대진표/결과]
  - 개요: `GET /api/v1/tournaments/{year}/{id}`
  - 참가선수: `GET .../participants` (이름/단체 검색), 등록은 ADMIN 모달
  - 조편성: `GET /api/v1/competitions/{competitionId}/groups`, 등록/수정 ADMIN
  - 대진표: `GET /api/v1/competitions/{competitionId}/matches` — 토너먼트 브래킷 컴포넌트(라운드별 컬럼) 또는 리그 테이블

### 3.9 공지사항 / 게시판(+댓글)

- 공지사항 목록/상세: `GET /api/v1/notices`, `GET /api/v1/notices/{id}` (관리자 등록/수정 폼 별도)
- 게시판 목록/상세 + 댓글: `GET /api/v1/boards`, `GET /api/v1/boards/{id}`, 댓글 `GET/POST /api/v1/boards/{id}/comments`
- 댓글은 `comment_depth`를 이용한 1단계 대댓글 UI 고려(트리 렌더링, depth 0/1만 지원 권장).

### 3.10 로그인/회원가입/마이페이지

- `/login`: `POST /api/v1/auth/login`, 실패 시 필드 하단 에러 메시지.
- `/signup`: `POST /api/v1/auth/signup` — user 테이블 필드(닉네임, 실명, 비번, 연락처, 이메일, 생년월일, 성별, 클럽명 등) 폼 매핑.
- `/mypage`: `GET/PUT /api/v1/users/{userId}` — 본인 정보 수정, 최근 참가 대회/경기 목록.

## 4. 공통 UI 컴포넌트 설계

| 컴포넌트 | 사용처 | 비고 |
|---|---|---|
| `<DataTable>` | 선수 목록, 랭킹표, 참가선수 현황 | 정렬/페이지네이션/검색 slot 지원 |
| `<PlayerSelect>` | 경기 등록 | 비동기 검색(react-query) 드롭다운 |
| `<SetScoreGrid>` | 세트 점수 입력/상세 | 입력 모드/읽기전용 모드 props 분기 |
| `<StatusBadge>` | 대회/경기 상태 | SCHEDULED/IN_PROGRESS/COMPLETED/CANCELLED 색상 매핑 |
| `<RankingChart>` | 통계/랭킹 | recharts 기반, 기간 필터 props |
| `<TournamentBracket>` | 대진표 | match_round 기반 트리 렌더링 |
| `<CommentThread>` | 게시판 상세 | depth 기반 들여쓰기 |
| `<AdminOnly>` | 등록/수정/삭제 버튼 wrapping | role !== 'ADMIN' 시 렌더링 안 함 |

---

## 5. 상태관리 & 데이터 흐름

- 서버 데이터(목록/상세)는 전부 React Query로 캐싱, `queryKey`는 API 경로 기반으로 통일 (예: `['matches', matchId]`).
- 폼 상태는 react-hook-form, 제출 시 zod 스키마로 1차 검증 후 API 호출 (백엔드 명세서 2.5 에러 코드와 매핑해 필드별 에러 표시).
- 로그인 상태(Access Token, role)는 Zustand 전역 store + Next.js middleware로 보호 라우트 처리 (`/matches/new`, `/*/edit` 등 ADMIN 전용 경로).

## 6. 반응형 / 접근성 기준

- 브레이크포인트: `sm(640) / md(768) / lg(1024) / xl(1280)`.
- 표(DataTable)는 모바일에서 카드형 리스트로 전환.
- 세트 점수 입력은 모바일에서 숫자 키패드(`inputMode="numeric"`) 사용.
- 색상만으로 상태를 구분하지 않고 텍스트 라벨 병행 (승/패, 상태뱃지 등).
